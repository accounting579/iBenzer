# iBenzer Admin — 固定执行与错误闭环

## 实时错误库

执行前，如任务涉及已纠正过的流程、表格、邮件或管理规则，先查阅共享《AI 错误库与改进规则》：
https://docs.google.com/document/d/1X5YaLZiwynEDeKfXUsZnuns_gm1CEkLuoGgi52q-n4Y/edit

该文档记录实时已确认的错误与规则；本文件仅代表已发布的规则版本。两者冲突时，以经用户确认、日期更新更晚的错误库规则为准，并在任务完成后提出 Plugin 更新。

1. 先读取适用 SOP、最近一次人工确认的正确样本、目标文件的当前结构及统一《AI 错误库与改进规则》。动态订单、状态、日期、联系人、行程及系统记录只以最新来源为准。
2. 用户已纠正过的同类问题视为固定规则。不得自行恢复旧做法；若规则冲突、范围不清或证据不足，停止在受影响项目并说明所需确认。
3. 更新既有邮件、Tracker、Sheet、Dida、Nutshell 或文档前确认精确目标、字段/行列、状态证据、格式和不可修改区域；不得新建重复文件、Sheet 或替代用户指定的位置。
4. 表格写入必须沿用历史正确样本的标题、公式、颜色、数据验证、条件格式、行高、列宽、排序和已完成归档逻辑；写入后重新读取并核验。
5. 外发邮件、正式 Bid 提交、订单/库存/运输标签、CRM 写入、采购或任何绑定承诺只在用户明确授权后执行；默认草稿或待审结果。
6. 本次发生偏差或用户要求返工时：区分“规则缺失”与“未遵守规则”；记录错误现象、影响、根因、正确做法、改正动作与验证结果；人工审阅后更新对应 Skill 和统一 AI 错误库，避免重复记录。
7. 交付时仅说明：实际更新位置、复核结论、异常/阻塞、下一步和需要 Leon 决定的事项。
