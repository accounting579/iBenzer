# iBenzer Bid Review & Submission

## 公司固定执行与错误闭环
开始此工作流前，先读取 [公司固定规则](../../references/company-operating-rules.md)。该规则适用于本 Skill 的所有步骤；如与当前用户明确指令冲突，以用户当次明确指令为准。


Use the current solicitation and current internal records as authoritative. Historical examples are supporting evidence only.

## Workflow

1. Locate the current bid in Google Drive. Start from `6, Virtual Assistant`. If the user provides a bid file/folder directly, use it first.
2. Check `Bid - VA` before analysis. Read the current-year `Bid List`, then `Bid Result` if present. Read `CRM` when customer history matters. Use `Account Info ` only when a registered platform login is needed; never expose credentials.
3. Classify:
   - `Directly Relevant`: protective shells/cases, sleeves, bags, headsets/headphones, charging accessories/carts, or other iBenzer-type products.
   - `Indirectly Relevant`: laptops/tablets/Chromebooks/Apple devices or related hardware where participation may be through accessories, Rocky Tech, or another approved strategy.
   - `Not Relevant`: unrelated technology services/infrastructure or work outside the product scope.
   - If uncertain, use `Need Confirmation`.
4. Extract all current bid facts: entity, bid number, issue/due dates, submission method, products, quantity, specs, alternatives, samples, lead time/in-hands date, contract period, award method, criteria, insurance/notary/bond/state filing needs, mandatory forms, addenda, signatures, attachments, question deadline/contact, manufacturer/catalog/price-list needs, shipping/special requirements.
5. Build a document matrix. Give each item exactly one status:
   `Completed`, `Missing`, `Signature Required`, `Need Confirmation`, `Not Applicable`, `Waiting on Pricing / Bid Line`, or `Waiting on External Document`.
6. Search historical submitted files for the same agency first. Prefer successful/submitted examples over drafts. Reuse only stable company information, formatting, attachment patterns, and proven workflow. Never copy old dates, prices, discounts, bid numbers, signatures, quantities, or agency-specific answers without current support.
7. Prepare the package. Fill stable company information only after verification. Mark all authorized-signature locations. Prepare product/specification sheets, cover letter, catalog, warranty, drop-test certification, CA65, flyers, manufacturer literature, or price-list material when required/relevant. Check addenda immediately before submission.
8. Final validation: no required blanks; all mandatory forms; signatures/initials; pricing math; line/manufacturer references; supported lead time; correct attachments; addenda; filenames; submission method; mailing label/tracking/platform requirements; tracker status.
9. Do not formally submit, send external email/message, sign, or make binding commitments without explicit human approval.
10. After submission, update the tracker with verified submit date, method, tracking, submitted SKU/quote, and submitted-file link. Record result follow-up and award/tabulation data when available.

## Fact discipline

Priority: `current live system/current solicitation > current tracker/files > confirmed SOP/template > historical example`.

Never guess price, discount, deadline, submission status, bid/line number, manufacturer, signature status, tracking number, award/result, or legal/accounting classification. If a fact cannot be verified, mark it `Need Confirmation` and state exactly what source/person is needed.
